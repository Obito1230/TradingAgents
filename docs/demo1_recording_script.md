## 分镜脚本

### 00:00–00:25 ｜ 开场 · 提出问题

**画面**：打开 `trading_memory.md`，定位到 `REFLECTION:` 段落，高亮简短的 2~4 句反思文本。

**操作**：无命令，仅滚动查看文档。

**讲解词**：
> 大家好，这是三层记忆多智能体交易 Agent 的 Demo 演示。
>
> 传统多智能体交易系统，在每笔交易结算之后，只会生成短短 2 到 4 句反思文本。这种简短反思有明显缺陷：它只保存最终决策文字，丢弃了多智能体之间完整辩论、工具调用的中间痕迹。系统无法跨轮次发现隐藏矛盾，比如数据口径不一致、关键证据缺失这类深层问题。
>
> 这就是我们这套三层记忆架构想要解决的痛点。

**字幕要点**：痛点：传统 Agent 反思仅保存简短文本，丢失全链路辩论痕迹，难以发现跨轮次隐性矛盾。

---

### 00:25–00:55 ｜ 架构介绍

**画面**：打开 `docs/memory_three_layer_design.md`，展示三层架构图，重点圈出 L1 层。

**操作**：无命令，浏览文档 §2。

**讲解词**：
> 我们设计了三层记忆架构。最核心是 L1 层：每一笔交易结算时，持久保存完整多智能体辩论痕迹，作为结构化历史事件存入本地记忆库。
>
> 这和 FinMem 等现有 LLM 记忆方案不一样：现有方案大多只压缩成简短总结；而我们保留完整辩论证据，用于事后归因复盘。L2、L3 层负责更高层级归纳，本 Demo 先验证 L1 闭环。

**字幕要点**：创新点：L1 存储完整多智能体辩论痕迹，用于事后归因；区别于传统压缩式记忆。

### 00:55–01:40 ｜ 现场演示：事件落库

**画面**：
1. 终端输入命令执行；
2. 分屏：一边终端运行，一边打开 `trading_lessons.md`，观察文件新增内容（视频加速播放，实际执行约 4 分钟）。

**操作命令**：
```bash
python scripts/settle_now.py --ticker 300750.SZ
```

**讲解词**：
> 现在我们执行结算脚本，针对标的 300750.SZ 完成交易结算。结算完成后，系统会自动生成一条受保护的结构化 EVENT 事件，写入 `trading_lessons.md`。
>
> 大家可以看到，文件从空文档，新增一条带 PROTECTED 标记的事件记录，包含五字段摘要、JSON 指针，完整保存本次交易的全部辩论与复盘信息。这条事件将作为历史经验，供后续同标的决策使用。

**字幕要点**：结算触发事件持久化 → EVENT 写入 trading_lessons.md，标记 PROTECTED。

### 01:40–02:20 ｜ 核心价值实证：记忆注入到新决策

**画面**：
1. 打开 EVENT，高亮 `Missed Factors` 和 `Self-critique` 两段；
2. 切换到终端，执行审计脚本；
3. 高亮输出：`past_context: 4260 chars`、`L1 events (this ticker)`。

**操作命令**：
```bash
python scripts/check_injection_audit.py --ticker 300750.SZ --date 2026-04-08
```

**讲解词**：
> 打开刚刚入库的事件，系统自动复盘，捕获到两次关键缺陷：第一，缺失证据被模型误判为利好；第二，266.7 亿这个数据口径不一致，整条链路没有自动复核。
>
> 接下来运行审计脚本，验证记忆注入。可以看到，本次推理加载了 4260 字符的历史上下文，成功召回该标的对应的 L1 历史事件。
>
> 重点：记忆只是注入经验素材，不会强制模型复用旧决策。上次决策建议 327–332 区间建仓；本次模型读取记忆，结合现价 383.82，给出 Overweight，但更新判断：等待回踩 365–377 再分档吸纳。记忆提供经验，但是模型基于当前行情重新评估。

**字幕要点**：
- ✅ 自动捕获隐性缺陷
- ✅ L1 事件成功注入上下文
- ⚠️ 记忆注入 ≠ 强制复用旧结论
