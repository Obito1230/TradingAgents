## A. 实验设计口径（**阻塞后续实验，优先回答**）

### A1 · 论文评估集按什么规则盲选？

- **背景**：当前 `exp_scenarios.json` 的 3 个场景是用 `scan_demo_pool.py --min-abs 0.04` **按已实现涨跌筛出来的**，即在因变量上选样本。它只能用于 pilot（链路验证），**不能作为论文数字**。你们自己的 `demo_pool_ashare.json` readme 也写了"论文评估集必须按协议盲选，与结果无关"。
- **可选项**：
  - (a) 规则化盲选：先定区间 `[S,E]` + 固定标的池 + 固定步长（如"每个标的的第 k 个交易日"），写进实验日志后再取数；
  - (b) 随机抽样 + 固定随机种子；
  - (c) 按"与既有语料时间不重叠"自动切分（先到先得，不看结果）。
- **我的倾向**：(a)。规则最容易被审稿人接受，且可复现。

**答：** (a)

### A2 · `Hold` 在命中率指标里怎么处理？

- **背景**：P1 实测暴露——不定义清楚就会出**假差**。`on` 臂 hit=0.67、`off` 臂 hit=0.50，看似有差；但**配对口径下可计分对只有 2 对，且两臂结果完全相同（Δhit = 0）**。0.67 vs 0.50 全部来自 `601318.SS` 上 `off` 给了 Hold 导致它的分母从 3 变 2。
- **可选项**：
  - (a) **排除该配对**（两臂只要有 Hold 就整对丢弃）——最保守，样本进一步变小；
  - (b) **记为第三类**（Hold 计入分母，正确率按方向+中性三分类算）；
  - (c) **单独报告**：主指标只算非 Hold，Hold 比例作为次要指标单独列。
- **我的倾向**：(a) 作主指标 + (c) 的 Hold 比例作次要指标。

**答：** (a)作主指标

辅助指标`score = +1 / -1 / 0`，用来观察整体行为：记忆是否改变模型的交易激进程度、综合得分

辅助指标 Hold 率单独拎出来，单独分析：看 on/off 臂，记忆开启后模型会不会变得更谨慎。

## B. 声明与限制（影响 claim 强度与 limitation 章节）

### B1 · `get_fundamentals` 的回溯泄漏怎么处理？

- **背景**：基本面分析师调用的 `get_fundamentals` 走 yfinance 的 `ticker_obj.info`（Alpha Vantage 同名接口也一样），**两者都忽略决策日期**，返回**运行当天**的快照（PE/PEG/PB/市值/52周高低/50·200日均线/Beta）。yfinance 还会在表头写 `# Data retrieved on: <今天>`。对 2026-03-04 的决策，等于把 9 月的估值喂进去。**免费数据源没有 point-in-time 版本，过滤不出来。**
- **性质**：这是**两臂共享**的混淆项，不像记忆泄漏那样只偏向 `on` 臂 → **不推翻 A/B**，但会影响"绝对命中率"的外部效度。
- **可选项**：(a) 声明为 limitation；(b) 把 `get_fundamentals` 从工具表里摘掉（保留三个**已做日期过滤**的报表工具：balance sheet / cashflow / income statement）；(c) 买 point-in-time 数据。
- **我的倾向**：(a) 主 + 视情况补 (b)。注意 `get_balance_sheet`/`get_cashflow`/`get_income_statement` 已由 `filter_financials_by_date` 做了日期过滤。

**答：** 暂时先(a)

### B2 · 要不要引入 A 股新闻/情绪数据源？

- **背景**：A 股的 sentiment 源（StockTwits/Reddit）基本为空，yfinance 对 A 股的新闻覆盖也薄；当前 `disabled_sources=social,macro,prediction_markets`。这是显著的数据可得性缺口，两个臂都一样。
- **我的倾向**：作为 limitation 声明；若老师有渠道，接一个国内新闻源会明显提升演示观感。

**答：** 暂时作为limitation声明

### B3 · v1 用 `alpha` 符号做市场状态代理，可以接受吗？

- **背景**：真正的市场 regime 应由市场数据（协方差/波动率/签名法）检测，而非单次决策的结果符号。L2 的完整状态向量在 v3，v1 的 alpha 符号是过渡占位。若接受，需要在论文里声明这个降级。

**答：**接受

### B4 · 要不要在存档里记录工具调用名？

- **背景**：`full_states_log` 只存各 agent 的报告和辩论历史，**不记工具调用与原始工具输出**。所以我们**无法从存档判断** `get_fundamentals` 到底有没有被调用过（报告正文里没有 yfinance 的 `Data retrieved on` 表头，既不能证明调用过、也不能证明没调用）。
- **影响**：论文的"可复现/可审计"章节会缺一块；也是 B1 无法给出确定答案的原因。
- **我的倾向**：补（改动小，且直接增强可审计性）。

**答：** 补

## C. 机制与后续（影响 v2/v3 实现）

### C1 · 淘汰优先级：访问制还是时间制？

- **背景**：`_recency_key` 的主键是 `last_accessed` / `hits`，`trade_date` 只排第三。含义是"常被读到的条目几乎免疫淘汰，而重要但没被读到的排在琐碎新条目之后"。这与"大亏/熊市记忆要留"的目标是**一致还是相冲**需要判断。当前另有 `protected`（|alpha| ≥ 10%）与 `min_events_per_direction`（方向下限）两道保险。
- **可选项**：(a) 保持访问制；(b) 改成 `trade_date` 优先、访问度做次级。
- **我的倾向**：这条直接影响 L2/L3 的设计，越早定越好。

**答：** 推荐采用**混合淘汰优先级方案**，不单纯选择 (a) 纯访问制或 (b) trade_date 优先的纯时间制。

现有机制的`protected`标记（|alpha|≥10%）、`min_events_per_direction`下限规则，已经对重大盈亏记忆形成兜底保护，规避了 “沉默的极端大亏记忆被误删” 的核心风险。

在常规未保护记忆的淘汰打分逻辑中：以**trade_date（交易发生时间）计算新鲜度作为基础项**，`hits/last_accessed`访问频次作为加权修正项，同时保留`|alpha|`极端收益权重与冗余惩罚项。

该设计兼顾两点：

1. 新生成记忆具备基础曝光机会，解决纯访问制下新条目 hits=0、难以留存的冷启动缺陷；

2. 被 L2 反复检索命中的高复用记忆，依靠访问权重获得更高留存优先级，契合多智能体跨标的经验复用的设计目标。

   

   trade_date 不再是简单的第三排序字段，而是进入打分公式作为基础分量；访问度保留权重，但不再作为唯一主键。该方案改动可控，直接适配 L2 检索与 L3 记忆蒸馏的后续设计，权重参数预留可调空间，后续可通过回测消融实验对比不同权重组合效果。

   ### 具体可操作的方案

   淘汰分数的公式score = w_recency · recency_norm + w_freq · log1p(hits) + w_extremity · |alpha|_norm − redundancy_penalty

   - `recency_norm` 用 **trade_date** 算（不是 last_accessed），保证新条目有机会被看到
   - `hits` 用 log1p 平滑，避免高访问条目垄断
   - `|alpha|` 保留极端度信号
   - **权重建议**：`w_recency=0.4, w_freq=0.3, w_extremity=0.3`（比草案里的 0.4/0.2/0.4 更平衡，让访问度有发言权，但不至于压倒时间）

   这样：

   - 新写入的极端事件，因为 `|alpha|` 高 + `recency` 高，不会被埋没
   - 常被检索的“活记忆”，因为 `hits` 高，能留在库里
   - 保护集负责兜底最极端的大亏

   我说的公式可供参考，你又更好的想法可以用你的

### C2 · 复盘 agent 用哪一档？

- **背景**：现在是 **quick 档 + 思考开启**（`postmortem_llm=quick`, `TRADINGAGENTS_POSTMORTEM_THINKING=true`）。管线其余部分思考关闭。升到 deep 档更贵，但"复盘抓到原管线缺陷"（例如 300750.SZ 那次的 266.7 亿口径/算术不一致，全队无人质疑）正是论文的定性亮点。

**答：** 批量主实验维持 quick 档位并开启思考，控制 API 开销与风控风险；由于缺陷无法在运行时预判，批量阶段统一使用 quick。待全部实验跑完后，人工筛选关键案例（如 300750.SZ 财务口径不一致案例），单独重新执行 deep 档位复盘，用于论文展示复盘 Agent 识别管线缺陷的能力，不需要全部样本切 deep。

### C3 · L2 是否就按"情境相似度检索、打破 ticker 边界"来做？

- **背景**：**P1 给了实证动机**。语料里有一条正好警告本次错误（"对高盈利质量、低杠杆、正现金流的龙头，不能仅凭均线空头排列给 Underweight"），但：
  - 它在 legacy 决策日志的 `DECISION` 正文里（L1 事件里没有）；
  - 它属于**另一个标的**，而跨标的段只注入 tag + 2–4 句反思，**不含正文**；
  - 结果 `on` 和 `off` **都没看到它**，两臂都在 `600519.SS` 上给了 Underweight（实际 +12.62%，都错）。
- **含义**：两臂同时失手**不是记忆内容差异，而是检索覆盖不足** → 正是 L2 要解决的问题。
- **问题**：这条实测证据值不值得单独写进论文的问题动机？L2 的设计是否就以此为主线？

**答：** 如果实现难度不高，或有成熟相关方面论文参考的话可以一试，打破ticker边界可以试一试，但如果实现难度较大，就按“memeory_three_layer_design.md”中L2部分的原计划
