# 计算机设计大赛实现路径 

> **目标**:以"TradingAgents 三层记忆系统"为作品,参加**中国大学生计算机设计大赛**(校赛 → 省赛 → 国赛),先做出**可演示、可打磨**的作品,再为后续论文复用同一套代码与实验证据。
>
> **配套文档**:技术设计 `docs/memory_three_layer_design.md` · 定位与文献 `docs/positioning_and_related_work.md`
>
> **重要前提**:大赛名称/赛道/规则每年以**你所在学校当年发布的校级通知**为准(如[2026 年第 19 届预通知](https://ss.dlut.edu.cn/info/1371/30722.htm)、[校级选拔示例](https://cxcy.sdut.edu.cn/article/1828));报名通常先经校赛选拔。本文按"人工智能应用/软件应用类"通用口径写,若当年没有此类赛道则降级挂在最接近的赛道,并调整申报口径。
>
> **总时长建议**:6–8 周(团队 1–3 人);默认 LLM API 预算有限,实验先用 quick 档模型跑通、deep 档只用于最终演示与关键复现。

---

## 0. 全局原则(贯穿所有阶段)

1. **演示优先**:比赛评委看的是"系统在运转 + 讲得清新在哪",不是论文深度——每个阶段结束都要有"能给别人看 3 分钟"的东西;
2. **创新口径纪律**:对外只讲"为多智能体交易辩论流水线设计的**记忆架构**"(§3.1 claim 口径),机制名词一律归因已有工作(见 `positioning_and_related_work.md` §3.3,违反即被 FinMem/MemoryBank 击穿);
3. **真实数据、诚实披露**:用真实历史行情/新闻,声明成本模型与局限;不夸大收益;
4. **证据复用**:比赛阶段攒的 A/B 与消融数据 = 论文实验底稿,协议按论文标准做(时间一致切分等),一次做对,两处受益;
5. **成本记账**:每次 run 记 token/费用,总预算在开跑前定死(quick 档为主)。

## 2. 分阶段实施细节

### P0 · 立项与规则核查

- **做**:查学校教务处/创新创业学院当年通知,确认赛道大类与提交物清单(作品说明书、演示视频、源码、查重/AI 使用声明要求);定作品名与一句话定位(复用 `positioning_and_related_work.md` §1 对外口径三句话);组队分工(建议:实现/数据、可视化、文档答辩各一)。
- **技术/工具**:无(办公类)。
- **要查的文献**:当年大赛通知与章程([2026 预通知](https://ss.dlut.edu.cn/info/1371/30722.htm));确认是否有"AI 生成内容比例/AI 使用披露"条款——若有,作品主体(记忆系统代码、可视化、说明书)必须是人工原创,LLM 仅作为作品内被调用的组件,申报口径据此写明。
- **验收**:赛道、队名、提交物清单、AI 使用声明口径四项定稿,写进申报表草稿。

### P1 · 基线跑通与技术准备

- **做**:
  1. 本地装好环境(python 3.12 + `pip install -e .`),配好一家 provider 的 key(默认 openai 兼容即可);
  2. 跑通一次完整分析 `main.py` 或 `tradingagents analyze`,看懂一次 run 的**记忆链路现状**:`store_decision` →(下次同 ticker 跑)→ `_resolve_pending_entries` 结算反思 → `get_past_context` 注入 PM(`memory.py` / `trading_graph.py`);
  3. 建**演示标的池**(关键!):跨市场且日期足够靠后(收益已实现可确定性取得)——如 `AAPL`(US)、`0700.HK`、`RELIANCE.NS`、`BTC-USD`(加密)各 3–5 个历史日期;标注每例预期成本;
  4. 搭成本记账脚本(每次 run 前后记录 token 数与耗时)。
- **技术**:Python 3.12、LangGraph/LangChain、yfinance、`.env` 配置、`TRADINGAGENTS_*` 环境变量;读懂 `tradingagents/graph/trading_graph.py` 与 `agents/utils/memory.py`。
- **要查的文献/资料**:
  - TradingAgents 论文(arXiv:2412.20138)——基线架构与"公平对照"口径;
  - [Agentic Trading(ESWA 综述,2026)](https://ar5iv.labs.arxiv.org/html/2605.19337)——§2 评估协议审计:知道我们实验必须避免哪些坑(时间切分、成本、幸存者);
  - LangGraph 官方文档(节点/条件边/持久化)作为技术手册。
- **验收**:同一 (ticker,date) 连跑 2 次复现;能指出现状记忆链路每一环的代码位置;成本基线记录在案。

### P2 · v1 核心:L1 复盘闭环(作品的技术主体)

- **做**(严格按 `memory_three_layer_design.md` §3 实现):
  1. 配置项:event_alpha_threshold / protect_threshold / max_event_entries 等(`default_config.py` + env 覆盖);
  2. 复盘 agent:`postmortem_agent.py`,输入 = 读 `full_states_log_<date>.json` 全量辩论痕迹 + 结算数字,输出 = 结构化 Pydantic `EventPostmortem`(摘要/依据/未预见因素/可迁移教训),`with_structured_output` + 自由文本回退;
  3. 存储:新增 `trading_lessons.md` 条目(EVENT 前缀、元数据、摘要、指针、指纹占位),`memory.py` 按前缀分流解析(旧决策日志不动);
  4. 挂载:`_resolve_pending_entries` 结算后 → |alpha| 判定 → 复盘 agent → 写条目;维护批次(上限/保护集/冗余剔除)先做简化版;
  5. 注入改造:PM `lessons_line` 加"L1 事件段"(v1 先用 recency top-k 代替检索);单测补齐。
- **技术**:Pydantic v2、langchain `with_structured_output`、markdown 原子写(tmp+replace,复用 `_apply_rotation` 模式)、pytest/ruff;LLM 用 quick 档跑通、deep 档最终复核。
- **要查的文献**:
  - Reflexion(自我反思 episodic buffer)——复盘 agent 形态对照;
  - TradingAgents 自带 reflection 实现(源码即文献)——我们的基线"2–4 句反思只读决策文本",写清差异;
  - FinMem(arXiv:2311.13743)——它的事件采样/记忆粒度与我们的差异,写进说明书"创新点"时引用。
- **验收**:造一个演示场景——选一个历史上确实大涨/大跌的 (ticker,date),跑两次(第一次产生 pending,第二次结算触发复盘),确认:阈值命中、复盘 agent 读了辩论全文、条目落库且正文不含全文、旧决策日志无破坏。

### P3 · 打磨 + 可视化仪表盘(比赛胜负手)

- **做**:
  1. 本地 Web 仪表盘(推荐 Streamlit,快;有前端能力可 FastAPI+React),页面:记忆库卡片流 / 当前 run 注入内容预览(top-k + 准则段)/ 遗忘与保护集可视化 / A-B 对比视图;
  2. 可视化"记忆在运转":事件触发的复盘过程动画化(结算→阈值命中→读辩论→结构化落库),检索 top-k 高亮,蒸馏准则面板(P7 若有);
  3. 演示叙事脚本:3 分钟主 Demo(默认场景)+ 1 分钟备选(加密/非美市场/无数据边界);
  4. 打磨体验:进度展示、错误恢复提示、长 run 可中断续跑。
- **技术**:Streamlit / Plotly / ECharts(前端)、pandas;复用 CLI 的 rich 面板思路;`reporting.py` 报告结构可作仪表盘数据源。
- **要查的文献/资料**:可视化类参考开源项目(非论文);此处文献重点不是论文,而是**把答辩叙事对准 §3 claim**:每个画面配一句"这解决现基线的什么问题"。
- **验收**:脱离开发者电脑也能讲清 Demo(录屏);评委问"这层解决什么"时有 30 秒标准答案。

### P4 · 证据:A/B 与消融(说明书与答辩的底气)

- **做**:
  1. 配对 A/B:同一批 (ticker,date) × 记忆开/关 × 每档 ≥5 轮(quick 档),记录方向命中率、模拟 alpha、注入 token 预算;
  2. 消融 P1(关 L1 回基线)、P2(关 L3 只淘汰不蒸馏,若已实现);P3(L2 阶梯)留待 v3/论文;
  3. 统计:配对 t 检验/符号检验,别只看均值;固定 provider/温度/种子;
  4. 结果整理进"技术说明书"的实验章节,图表即答辩材料。
- **技术**:pandas、scipy、backtest 协议(时间一致切分:调参只在训练期日期;成本声明:无成本模型就写明);LLM 采样噪声按 README「Reproducibility」处理。
- **要查的文献**:FinMem(实验设置与指标参照)、MemoryBank(遗忘对照)、GA(检索/反思对照)、[Agentic Trading 综述](https://ar5iv.labs.arxiv.org/html/2605.19337)(报告清单:逐项打勾证明我们协议严谨)。
- **验收**:说明书里能放一张"记忆开/关"对比表 + 一段消融结论,且每项声称都能指到代码开关。

### P5 · 稳健性与工程打磨

- **做**:边界场景(加密货币无基本面、非美市场 ticker、缺数据/限流)、长 run 断点恢复(checkpoint 开关实测)、成本控制(llm_max_retries / temperature / 缓存)、异常与日志、README 与安装说明、Docker 可选;给演示机准备"干净环境一键启动"脚本。
- **技术**:现有 LangGraph checkpoint、logging、`TRADINGAGENTS_*` 配置;容器化(可选)。
- **要查的文献**:无需新论文;回归 `tests/` 既有 60+ 用例防止改坏(v1 改动会碰 `test_memory_log.py`,同步更新)。
- **验收**:演示机从零到跑通全流程 ≤10 分钟;拔网线/断点场景有预案。

### P6 · 申报材料与答辩演练

- **做**:
  1. 作品说明书(结构:背景问题 → 架构总览图 → 各层设计 → 实现 → 实验 → 局限与未来);架构图直接复用设计文档 §2;
  2. 演示视频(5–10 分钟,OBS 录屏+配音):讲"现状缺陷 → 我们架构解决 → 证据"三段;
  3. 答辩 PPT + Q&A 演练:预设问题库(为什么不用 FinMem?为什么事件触发?为什么三层的顺序?记忆会不会过拟合?成本多高?);
  4. 按校赛→省赛→国赛的时间表倒排提交。
- **技术**:OBS、剪映/PPT;Q&A 口径一律走 claim 纪律(见 P0)。
- **验收**:找 1–2 个不懂代码的同学试听答辩,能复述"你的作品解决什么问题、新在哪"。

### P7 · 可选冲刺加分

- L3 蒸馏最小演示(淘汰队列 → 蒸馏准则面板)或 L2 粗桶检索,任一能显著提升"架构完整性"观感;若时间不足,**明确写成"未来工作"即可**,不要牺牲 P2–P6 质量。

## 4. 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| LLM API 成本超预算 | 实验做不完 | quick 档为主;标的池限 15–20 例;每轮前定预算上限;A/B 各 ≥5 轮不贪多 |
| 采样噪声大,对比无显著差异 | 说明书没证据 | 固定 provider/温度/种子;配对设计;如实写"未显著"并给 token 预算收益(那是稳的) |
| 数据源限流/缺数据(非美/加密) | 演示翻车 | P1 就试全市场;P5 准备"无数据"边界演示脚本 |
| v1 改坏现有记忆链路 | 回归失败 | P2 起每步跑 `pytest`;`test_memory_log.py` 相关用例同步更新 |
| 赛道/规则与预期不符 | 白做 | P0 先确认当年通知;保留"挂靠最近赛道"备选口径 |
| 时间不够 P7 | 架构观感不完整 | 未来工作写清楚;优先保 P2–P6 |

## 6. 两个月 v1 执行计划(追加;目标:导师验收版"第一版应用系统")

> **当前进度基线(2026 起跑时)**:官方原项目(TradingAgents v0.3.1)**已在本地完整跑通过一次,尚未改动任何源码**。因此 W1 的"环境安装 + 首跑复现"视为**已完成**,只需补"精读主路径 + 标的池 + 成本基线 + 代码备份"。
>
> **与上文关系**:本计划是 §2 各阶段在两个月内的**执行切片**,v1 = 基线 + L1 复盘闭环 + 简化仪表盘 + 最小证据;L2/L3/完整实验/申报打磨全部后置(项目总工期数月,论文与比赛材料用 v1 之后的时间)。

### 6.1 v1 范围定义(先和导师对齐,再动手)

**进 v1(必须交付)**:
1. 干净基线分支 + 官方 demo 复现脚本;
2. **L1 复盘闭环全链路**:`|alpha| ≥ event_alpha_threshold` 结算判定 → 复盘 agent 读 `full_states_log_<date>.json`(全量辩论痕迹)→ 结构化 `EventPostmortem` → 写入 `trading_lessons.md`(EVENT 条目,含元数据/指针/指纹占位)→ PM 注入改造(事件段,recency top-k)→ 简化遗忘(上限/保护集/冗余剔除);
3. 配置项与 `TRADINGAGENTS_*` 覆盖(default_config);
4. 简化仪表盘(本地 Web):记忆库卡片视图 + 当前 run 注入内容预览 + 记忆开/关对比;
5. 演示标的池 5–8 例(含 1 例非美或加密),全流程可复现;
6. 单测/回归(不破坏既有 60+ 用例)、README、一键启动、Demo 视频初版;
7. 最小 A/B 证据雏形(1 组对比,quick 档)。

**不进 v1(明确后置,防范围蔓延)**:
- L2 状态检索(仅留 `state_fingerprint` 字段占位)、L3 蒸馏库(仅留淘汰队列接口与占位配置);
- 完整 A/B + P1–P5 全套消融(论文期做);
- 比赛申报材料打磨、P0 赛道申报(如校赛截止在两个月内,只做 P0 的"口径确认",材料后补)。

### 6.2 周表(8 周,含 1 周缓冲)
